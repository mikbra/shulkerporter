# Shulkerporter

A Paper 26.3 plugin with two magic shulker boxes:

- **Shulkerporter**: teleports its contents to the nearest other box with the same name.
- **Shulkerpopper**: a filtering hopper with a chest-sized inventory.

## How it works

1. **Craft:** shapeless, an *empty* black shulker box + a beacon gives a Shulkerporter. It can't be uncrafted, dyed or washed in a cauldron.
2. **Name:** rename it in an anvil, e.g. `Gate1`. Names are case-sensitive, but colours, formatting and whitespace are ignored (`Gate 1` = `Gate1` ≠ `gate1`). Channels are global, so a hard-to-guess name works like a password.
3. **Place** two or more with the same name in the same world. Fill them with hoppers as with any shulker box (vanilla rules apply: no shulker boxes inside).
4. **Send:** a redstone pulse (button, lever, dust, observer…) moves everything into the nearest box with the same name, by straight-line distance. Its chunk is loaded if needed. Items that don't fit stay behind. With no other box on the channel, nothing happens.

## Shulkerpopper

1. **Craft:** shapeless, an *empty* shulker box of any colour + a hopper + either
   - a **repeater**: matches by **item type** (any enchanted book matches any other), or
   - a **comparator**: matches the **exact item** (enchantments, potion type, name… must match too).
   The Shulkerpopper keeps the colour of the box. Change the mode later with `/shulkerpopper mode [type|exact]` while looking at a placed one, or holding one in your main hand.
2. **Place** it against the block it should feed: its base (the side you clicked) is the **output**, like a hopper's spout.
3. **Configure** the filter by putting one of each item it should collect inside. Everything in the box is the filter; an empty Shulkerpopper collects nothing. Shulker boxes can't be filtered (vanilla doesn't allow them inside shulker boxes).
4. **It then works like a hopper:**
   - it collects matching items from the container above it, and matching dropped items lying on top;
   - hoppers and other Shulkerpoppers may push matching items in from any side (other items stay in the hopper);
   - it passes items on through its base into chests, barrels, hoppers, shulker boxes, dispensers, droppers and furnaces (from above into the input slot, from the side into the fuel slot), always **keeping one of each type** so the filter stays configured;
   - a hopper (or Shulkerpopper) directly underneath takes precedence over the output while it has room, so a popper pointing sideways into a chest feeds the hopper below first and the chest only once that hopper is full;
   - nothing can pull items out of it, so a hopper underneath only receives what the Shulkerpopper passes on;
   - one item every 8 ticks, paused by a redstone signal.

With the resource pack it has its own look: a slate shell with flowing chevrons pointing to the output, an intake ring with inward arrows on top and a mode emblem (cyan: item type, violet: exact item).

## Building

Requires JDK 25 (Gradle downloads it automatically through the toolchain resolver).

```sh
./gradlew build          # build/libs/shulkerporter-<version>.jar
                      # build/resourcepack/shulkerporter-pack.zip (+ .sha1)
./gradlew runServer      # local Paper 26.3 test server with the plugin installed
```

## Resource pack (optional)

The pack gives Shulkerporters and Shulkerpoppers their own look, both as an item and when placed. Without it, players see a normal black shulker box (the item keeps the enchantment glint, unless disabled in `config.yml`).

Like [vane](https://github.com/oddlama/vane), the official pack is hosted on this repository's GitHub Pages site, one zip per version (`docs/resourcepacks/v<version>.zip`). Its URL and SHA-1 are baked into the jar at build time, so server owners don't need to configure anything (`resource-pack.mode: auto`). A jar built without a published pack serves its bundled copy from a small built-in HTTP server on port 25580 instead (`resource-pack.builtin.*`). Other modes: `official`, `builtin`, `url` (host it yourself, with `url` and `sha1`) and `off`.

The textures are generated by `java tools/PorterTextures.java` and `java tools/PopperTextures.java`; the models live in `resourcepack/assets/shulkerporter/models/block/`. The per-colour loot tables and item definitions are generated by `python3 tools/generate_shulker_overrides.py`.

Placed shulker boxes are drawn by the game's block-entity renderer, which can't be retextured per box. So the plugin draws the model over each placed Shulkerporter with two item display entities, a base and a lid. They are slightly larger than the vanilla box and hide it. The lid follows the vanilla lid animation when the box is opened. The displays are only shown to players whose client reported the pack as loaded, and they are never saved with the world. Turn this off with `placed-model: false`.

## Releasing

One-time setup: enable GitHub Pages for the repository (*Settings → Pages → Deploy from a branch → `main`, folder `/docs`*). Then set `packBaseUrl` in `gradle.properties` to the Pages address, e.g. `https://<owner>.github.io/<repo>`.

For each release:

1. If anything under `resourcepack/` changed since the last release, bump `version` in `build.gradle.kts`. A published pack must never change, because clients cache it by its hash; `publishPack` refuses to overwrite one.
2. `./gradlew publishPack build` copies the pack to `docs/resourcepacks/v<version>.zip` and builds a jar with its URL and SHA-1 baked in.
3. Commit and push `docs/resourcepacks/v<version>.zip` **before** handing out the jar, and wait for the Pages deployment to finish.

If the pack was changed without publishing it, the build warns and the jar falls back to serving its bundled copy, so a jar never points players at a pack that doesn't match.

## Commands and permissions

- `/shulkerpopper mode [type|exact]`: show or change a Shulkerpopper's filter mode (`shulkerporter.popper.mode`, everyone).
- Crafting: `shulkerporter.craft` (Shulkerporter) and `shulkerporter.popper.craft` (Shulkerpopper), everyone.

Admin commands (`shulkerporter.admin`, alias `/sp`):

- `/shulkerporter give porter [players]` / `give popper <type|exact> [players]`: give a Shulkerporter / Shulkerpopper.
- `/shulkerporter list [channel]`: list channels, or the boxes on one channel.
- `/shulkerporter rescan`: re-index the Shulkerporters and Shulkerpoppers in loaded chunks.

## Implementation notes

- The Shulkerporter is a black shulker box with a `shulkerporter:portal` PDC marker, `item_name`, `lore` and `custom_model_data` (`"shulkerporter"`, which the resource pack selects on). The Shulkerpopper is a shulker box of any colour with `shulkerporter:popper` and `shulkerporter:popper_mode` markers and `custom_model_data` `"shulkerpopper_<mode>"`.
- The bundled datapack (`src/main/resources/datapack`) overrides all shulker box loot tables so those components survive breaking, and copies the block's PDC onto the dropped item, so a mode changed after placing is kept. The item's look and lore are brought in line with its mode when it drops.
- Shulkerpoppers in loaded chunks are ticked by the plugin. Vanilla hopper rules are applied via `InventoryMoveItemEvent`; when a hopper's item is rejected, the plugin pushes the hopper's next accepted item instead, since Paper would otherwise stop that hopper.
- Placed boxes get the marker on their block entity and are indexed in `plugins/Shulkerporter/portals.yml`. The index repairs itself on chunk load and drops stale entries when they are used.
- Power is detected from block updates (`BlockPhysicsEvent`), with a 2-tick poll as backup, and sends only on a rising edge, with a 10-tick cooldown.
